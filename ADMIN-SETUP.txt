WHAT IS INCLUDED
----------------
- Main game site and game pages (including Ludo and Shinobu 3D model)
- Firebase Web configuration in firebase-config.js
- Google and phone OTP login UI on the game site
- Owner admin page (owner-admin.html)
- Realtime Database rules starter file (database.rules.json)
- Callable Cloud Functions source for owner coin actions and ban checks

IMPORTANT: NOT A ONE-CLICK DEPLOY
---------------------------------
The Firebase web config and database URL are filled in. Google and Phone providers
must also be enabled in Firebase Authentication, and arihant620.github.io must be
listed under Authentication > Settings > Authorized domains.

The secure owner actions will NOT work until Cloud Functions are deployed and the
owner Firebase Authentication UID is configured. The 8-digit game UID 97835276 is
NOT the same as the Firebase Authentication UID.

STEP A — FIREBASE AUTHENTICATION
--------------------------------
1. Firebase Console > Authentication > Sign-in method.
2. Enable Google and Phone providers (you have already done this).
3. Authentication > Settings > Authorized domains must include:
   arihant620.github.io
4. Open the website and sign in using the Google account you want as owner.
   Phone OTP can be used for players; use one consistent owner account.

STEP B — FIND OWNER FIREBASE AUTH UID
-------------------------------------
1. Firebase Console > Authentication > Users.
2. Find the owner account that just signed in.
3. Copy its Firebase UID (long string). This is NOT 97835276.
4. Do not publish this UID in frontend code. It is used only in the Functions env file.

STEP C — DEPLOY CLOUD FUNCTIONS (COMPUTER OR CLOUD SHELL REQUIRED)
-------------------------------------------------------------------
1. Install Node.js 20 and Firebase CLI, then open this project folder in a terminal.
2. Run: firebase login
3. This folder already contains firebase.json and .firebaserc for project ari-game-zone.
4. Copy functions/.env.example to functions/.env.
5. Edit functions/.env and replace the placeholder with the owner's Firebase Auth UID:
   ADMIN_AUTH_UID=THE_LONG_FIREBASE_AUTH_UID
6. Run: cd functions && npm install && cd ..
7. Run: firebase deploy --only functions

Cloud Functions deployment may require the Blaze billing plan and Google Cloud billing
account. Check current Firebase pricing before enabling billing. Do not expose private
service-account keys or admin credentials.

STEP D — DATABASE RULES
-----------------------
The included database.rules.json is a starter rule set matching the current game's
cloud profile writes. It allows each signed-in user to write their own profile record.
IMPORTANT: because the current game stores coins/XP in that same client-writable record,
these rules do NOT make the game economy cheat-proof. Do not claim coin balances are
fully secure until the game is migrated to server-authoritative reward/coin functions
and client writes to coin/XP fields are removed. Keep the database in locked mode until
you understand and intentionally deploy the required rules.

STEP E — GITHUB PAGES
---------------------
Upload the contents of the ari-game-zone folder to the repository root (not the outer
folder). Keep index.html at the repository root. Commit changes and wait for Pages.
Then open:
https://arihant620.github.io/ari-game-zone1/
Owner panel:
https://arihant620.github.io/ari-game-zone1/owner-admin.html

CURRENT OWNER PANEL ACTIONS
---------------------------
The panel provides add/remove/set-max coin controls and permanent/24-hour ban/unban
controls. The supplied backend looks up a target by its 8-digit game UID in
users/{firebaseAuthUid}. A player must sign in and have a cloud profile first.
Coin transfer between players (debit one account and credit another atomically) is not
implemented in this build; Add Coins is coin generation, not a transfer.

SMS NOTES
---------
Firebase Phone Auth may require reCAPTCHA and has SMS quotas/region restrictions. The
Firebase console currently showed a 10-SMS/day quota for this project. Test carefully.

SECURITY
--------
Never share OTPs, passwords, service-account private keys, or admin credentials.
The public Firebase web config is not a secret; security comes from Auth and Rules.

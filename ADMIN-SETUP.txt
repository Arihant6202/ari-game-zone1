ARI GAME ZONE — FIREBASE / DEVELOPER SETUP

1) Firebase project
- Keep the Firebase web app configuration in firebase-config.js.
- Enable Google sign-in and Realtime Database.
- Publish database.rules.json to Realtime Database > Rules.

2) Owner account
- Developer Mode is restricted to the verified owner Gmail: kumararihant625@gmail.com.
- The owner Player ID is 97835276.
- Open the website, sign in with that Gmail, then open Developer Mode.
- Do not share the owner Gmail or its sign-in access.

3) Player Mail and Gold Coins
- Developer Mode can send Gold Coins and a text message to one registered 8-digit Player ID.
- The player receives a Mail entry and must claim the Gold Coins in the Mail inbox.
- Message-only Mail is shown as read-only announcement text.
- Developer Mode > Send Mail can target one Player ID or ALL existing players, with message, coins and items.
- Developer Mode > Ban / Unban blocks a Player ID (must have logged in with Google once).
- A player must have opened the game and registered their Player ID at least once to be included.

4) Security notes
- Never publish permissive public read/write rules.
- The owner can read uidIndex and write adminGrants; each player can read their own grant queue and remove only their own delivered grants.
- A player can only read/write their own users/{authUid} data.

5) Deploy
- Upload the complete ZIP contents to the same GitHub Pages repository root.
- If Firebase rules are changed, publish them in Firebase Console as well; uploading the JSON file to GitHub alone does not publish database rules.

6) Moderators (version 1.12)
- Developer Mode > Staff: enter a Player ID (the player must have logged in with Google once) and press "Make Moderator". Maximum 3 moderators. Remove them with the Remove button.
- Moderator powers (enforced by database.rules.json, so publish it in Firebase Console):
  * +100,000 coins automatically once per calendar month (1st, India time), added when the moderator opens the game.
  * Can send coins / messages to any other player, at most 500,000 coins per calendar month in total. Never to himself, never items, no "send to all".
  * Can temporary-ban and permanent-ban players (not the owner, not other moderators, not himself).
  * Can unban TEMPORARY bans only. Only the developer can unban a permanent ban.
  * Can read the player list and ban support messages.
  * Has no self-coin tool and no self-level tool.
- Admin slots (10) are planned for a later version.

7) Owner-only IDs (version 1.13)
- Developer Mode > Owner-only IDs: add a Player ID there and only the owner can ban or unban it. Moderators cannot ban or unban those IDs (enforced by database.rules.json, publish it in Firebase Console).

8) Version 1.14 - Admins, new limits, separate pages
- Separate pages (all linked from owner-admin.html): owner-ids.html (developer only), staff.html (developer: moderators + admins; moderator: admins), support.html (ban messages, all staff), players.html.
- Moderator (max 3, added only by the developer): +200,000 coins on the 1st of every month (already received coins are untouched). Sends max 50,000 coins to ONE Player ID and 500,000 in total per month. Can message ALL existing players (never coins). Can ban (temp / permanent) players AND admins, unban temporary bans only. Can add admins and remove admins, except admins selected by the developer.
- Admin (max 10): +100,000 coins on the 1st of every month. Sends max 25,000 coins to ONE Player ID and 250,000 in total per month. Can message ALL existing players (never coins). Temp-ban and unban temporary bans only - NEVER a permanent ban. Can do nothing with the ID of the developer, a moderator or another admin (coins, mail, ban, unban - enforced by database.rules.json). A banned admin loses all admin powers.
- Admins added by the developer are locked (devSet): only the developer can remove them.
- Messages to ALL players skip the developer / moderator / admin IDs when an admin sends them (the rules refuse those IDs).
- PUBLISH database.rules.json in Firebase Console > Realtime Database > Rules (new nodes: admins, adminPaid, adminSent; modSent now stores per-ID totals in modSent/<uid>/to).
